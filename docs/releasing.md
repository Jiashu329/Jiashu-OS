# 发布与回退

开发期间运行 `npm run check`。检查顺序是类型检查、全部普通测试、生产构建、生产产物 DOM 冒烟；任一失败都会停止。测试文件自动发现，依赖 `dist` 的 `*-production-client.test.ts` 只在构建完成后运行。

GitHub 的 `main` 推送和拉取请求会执行相同的 `release:check`，另有独立的 **Browser acceptance / synthetic-browser-acceptance** 任务运行 `npm run test:browser`，保存实际 Chromium 截图、失败 trace 与报告。两类检查都需核对；CI 使用合成数据，不读取线上记录、不持有网站密钥，也不自动部署。

最终发布流程：

1. 完成并提交源码，确保 `git status --short` 为空。
2. 运行 `npm run release:check`。这会重新执行整套检查，并在 `dist/release-provenance.json` 写入源码提交、源码指纹、产物指纹、站点 ID 和检查结果。
3. 核对对应提交的浏览器 CI 结果与截图；iPhone Safari、健康权限和快捷指令安装／运行按[浏览器与 iPhone 验收](browser-acceptance.md)另行完成，未实测时如实记录。通过 Sites 获取当前站点的短期源码写入凭据。保持现有访问范围。
4. 使用关闭终端回显的 PTY 启动 `stty -echo && node scripts/publish-source.mjs`，在提示后通过标准输入传入工作流 JSON：`credential`、`project_id`、绝对 `archive_path`；设置 `sync_github: true` 可同时同步已配置的 GitHub `origin`。凭据只留在会话内存和子进程环境中。
5. 将脚本返回的 `project_id`、`commit_sha`、`archive` 原样传给适用的原生 Sites 保存／部署操作，确认部署成功。

发布脚本只接受已提交且通过全部检查的源码，不自动提交、不强制推送。如果源码、HEAD 或构建文件在验证后变化，必须重新检查和构建。独立运行 `npm run build` 适用于本地构建；它不替代完整发布检查。`mode: "verify"` 可只验证现有产物，不进行网络操作。

生产产物检查覆盖健康、同步、首页、财务、饮食、数据备份、快捷指令核对、AI 设置及助手初始化。390px 的 DOM 场景检查导航和对话控件的语义；它不验证浏览器绘制、触摸命中区域或 iPhone 快捷指令。真实绘制与交互由独立 Chromium 合成套件补充；390px 移动视口不等于 iOS Safari，iPhone 快捷指令仍须真机验收。

需要回退时，在 Sites 的已保存版本中选择此前成功的稳定版本并重新部署；不要强推 Git 历史或使用旧 `dist` 冒充当前提交。数据库迁移采用追加方式，回退前检查新迁移与旧 Worker 的兼容性；回退 Worker 不会撤销已经应用的数据迁移。

本轮开始使用独立的余额更正历史。早于本轮的 Worker 不理解这些记录，回退后可能显示原始余额。因此，已经产生更正／作废记录后，应优先前向修复，或选择同样支持有效余额计算的稳定版本；不能把代码回退当作数据回退。

P1 增加每日营养目标、饮食审计与历史恢复回执，完整备份业务格式仍为 v2；另为账户资料和财务目标增加独立编辑版本。应用迁移后旧 Worker 不提供这些界面与冲突保护，回退前须检查数据与写入接口兼容性，优先前向修复。


P2 再增加体重周期归档及操作回执、饮食模板及操作回执、财务分类生效历史，共 27 类业务表，并为账户增加可动用程度和比例。旧体重设置使用 `legacy` 周期标识；旧财务分类以兼容基线进入历史，不补造更早变更。迁移后回退到不理解这些字段与历史的 Worker，可能改变回顾结果或失去新操作保护，应先核对兼容性并优先前向修复。

食物库发布清单及对应旧版文件必须随源码一起发布，不能用更新当前文件的方式删除历史版本。记录、模板、恢复及备份的来源核验依赖这些归档。品牌数据必须先核验真实来源；通用检索别名与称重参考不构成品牌营养依据。麦当劳中国新增条目使用本次归档的官方每份数据。

备份仍兼容单个 v1／v2 文件，新下载格式另有清单与全部分卷。分卷业务上限为 16 MiB、40,000 行，每卷保持 8 MiB、20,000 行，并继续执行最多 48 条查询的安全恢复预算；旧 Worker 可能不支持新分卷组。发布检查应覆盖全组摘要、缺卷／混卷、原子恢复、旧备份兼容及字段冲突预览，不能因容量提高跳过完整性校验。最近备份的本机生成记录与本人保存确认不构成服务器对文件落盘的证明。

本轮还拆分日期范围、体重周期、睡眠分析、饮食模板和备份前端模块。发布验证需同时检查源码模块、构建后的内联装配及对应路由，避免只验证未压缩源码。完整范围与验收边界见 [P2 功能说明](p2-features.md)；不凭新增测试代码宣称真实浏览器、iPhone 或 iCloud 模板已经验收通过。

麦当劳中国官方餐品增加按官方规格每份计算的来源快照，克重保持未知。发布时保留旧TFDA文件及品牌原始数据归档、来源元数据和新目录清单；不要覆盖历史版本。保存了每份来源记录后，回滚须保留支持该快照模型的Worker，避免旧版误算重量或无法验证模板／备份。此变更不新增数据库表。


MiniMax改为创建者统一配置。此版本原地复用创建者现有的加密记录和身份绑定，无需新增表或复制密钥；业务数据和AI配额仍按当前用户隔离。回退到个人配置版本会让成员重新读取个人设置，可能再次要求成员配置密钥；不能把代码回退视为维持共享服务的办法。

家庭协作追加 `0020_family_books`：账本注册、邀请/成员、成员操作回执和财务操作者记录共4张表，现有财务数据不迁移。Sites会在上传Worker前应用新增迁移；保留既有迁移和主密钥。新表不加入可携带业务备份。发布验证覆盖邀请→接受→协作写入→撤销→旧请求拒绝、个人资源隔离、成员原子授权复核、编辑责任、导航和草稿范围。回退到旧Worker会失去协作入口及成员写入能力，不能把旧版个人scope解析作为家庭协作的兼容实现。

书影音本轮追加 `0028_douban_browser_source` 与 `0029_douban_library`。前者重建条目表以接受独立 browser 来源，并保留旧条目、详情、分类及索引；后者追加本地备注、标签、隐藏和独立修订字段。备份仍为 31 类业务表，旧备份缺少本地字段时不会抹去现有整理。产生 browser 来源记录后，回退 Worker 必须仍支持该来源，否则旧解析器无法读取这些记录；优先前向修复。清空预览同时校验本地修订变化，旧预览不能删除后来写入的备注。
