# 浏览器与 iPhone 验收

`npm run release:check` 保留现有类型检查、业务测试、构建与生产产物 DOM 检查。新增的 `npm run test:browser` 使用真正的 Chromium，分别运行桌面 1440px 与手机 390px 场景，检查首页饮食入口、体重快捷补录、营养填写与 AI 确认、结果不明的幂等重试、目标与财务冲突、记录历史恢复、键盘操作、横向溢出及草稿重开。

## 浏览器验收的运行边界

浏览器套件启动 `scripts/browser-fixture.mjs`，它只渲染当前源码的页面，使用固定合成身份；所有 API 由测试逐项拦截，未定义的请求失败，所有外部请求阻止。它不启动生产 Worker、不连接真实 D1、不读取个人记录或密钥，也不调用真实 AI。真实数据库隔离、版本校验、审计与幂等语义仍由现有 API／存储测试验证；浏览器套件验证这些响应下的实际界面行为。

普通本地或 CI 环境运行：

```sh
npm ci
npm run test:browser:install
npm run test:browser
```

GitHub 的独立 **Browser acceptance / synthetic-browser-acceptance** 任务在推送与 PR 上运行，保存截图、失败 trace 和 HTML 报告到 `synthetic-browser-evidence` 工件。截图是实际 Chromium 绘制结果，390px 项目属于移动视口模拟，不是 iOS Safari 真机。初次加入的截图作为可检查证据，不能将其称为已经人工批准的视觉基准。

套件的夹具服务明确拒绝 `SITES_MANAGED_LINUX_CONTAINER=1`。托管 Sites 环境仍须使用 `sites-preview` 与共享浏览器，不能用夹具或其他服务器绕开预览设施。本次托管环境尝试 `sites-preview` 启动超时且未返回可用 URL，现有浏览器的 New Tab 内容观察受 URL 策略限制；没有通过替代端口、原始 CDP 或改动应用来规避。这里不宣称本次托管浏览器实测通过；应以对应提交的 CI 任务结果及工件为验收证据。

## iPhone 快捷指令验收

硬件验收必须在 iPhone 上完成，网页回执和 Chromium 手机模拟不能替代。每类模板分别执行：

1. 在 iPhone Safari 登录本站，安装已列出的 iCloud 链接；记录手机 iOS 版本及核对指南版本。
2. 打开模板，核对网站地址、当前本人连接、健康数据来源和所需指标；清除模板中的过期连接配置。
3. 在健康授权中确认实际读取权限。缺少样本的指标可在网页核对范围中明确取消，不能补零或称为已接入。
4. 在 `/sync/templates` 点击“开始本次核对”，以服务器时间建立基线；随后在手机运行模板。
5. 返回网页检查新回执，并逐项对照健康 App 的日期、来源、数值。睡眠额外核对跨日归属及没有样本时的行为。
6. 再次运行，确认同一日期不会重复新增；已有手工更正与来源冲突必须按网站既有规则处理。
7. 若需要每天运行，在快捷指令“自动化”创建定时运行，核对当前 iOS 的立即运行／询问设置，再检查新的服务器回执；未配置自动化时如实保留“仅手动运行”。
8. 勾选网页真机清单后导出本次报告，保留模板链接、指南版本、所选指标、服务器核对起点及用户确认。报告不包含健康数值、连接密钥或登录信息。

报告仅表示用户已在设备上手动确认，不代表网站检查过 iCloud 模板内容，也不保证未来每次后台同步成功。指南版本和 iCloud 模板内容版本分别表述；不能因为本轮更新了指南而声称模板已更新或真机验收通过。
