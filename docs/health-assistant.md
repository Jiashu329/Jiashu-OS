# MiniMax 健康助手

入口为 `/health/assistant`，使用现有 ChatGPT 登录。页面预览健康摘要时不调用模型；只有提交问题并明确同意发送所选范围的数据后，服务器才请求 MiniMax。

## 网站内配置

登录后，从健康助手页进入“AI 设置”（`/settings/ai`），填写 MiniMax API 密钥、区域和账号可用的模型。默认模型为 `MiniMax-M3`；中国区选择 `cn`，国际区选择 `global`，应与密钥所属平台匹配。

保存后立即生效，无需修改代码或重新部署。修改模型或区域时，密钥留空表示保留原密钥；网页不会显示已保存密钥的任何部分。每位登录用户的配置独立，健康助手只使用本人的已保存配置。

“测试连接”只向 MiniMax 发送固定测试文本，不读取健康数据，需要单独确认可能产生的 API 费用。测试使用当前已保存版本，修改配置后需要重新保存和测试。连接测试与健康助手共用请求额度。保存成功仅表示配置已存储，实际模型权限和可用性以连接测试及真实请求为准。

删除密钥后停止后续调用；清除操作保留版本标识，避免旧页面的过期保存请求重新写回密钥。删除不会撤销已经发送到 MiniMax 的请求。网页不将密钥写入浏览器持久存储，也不把服务器加密密文发回浏览器。

## 服务端加密配置

MiniMax 密钥使用 AES-256-GCM 加密后存入 D1，随机 IV 与认证数据将密文绑定到当前用户。服务器主密钥 `AI_SETTINGS_ENCRYPTION_KEY` 保存在 Sites 的 Secret 环境变量中，与数据库分离。Sites 发布流程为这个站点自动准备一次主密钥，后续部署必须保留它；更换或遗失主密钥会使旧密文无法解密，需要用户重新填写 API 密钥。

本地预览可在未跟踪的 `.dev.vars` 配置独立的、标准 base64 编码的 32 字节随机主密钥。不要复用生产主密钥或将任何密钥提交到源码、GitHub 或聊天。原先直接使用全站 `MINIMAX_API_KEY` 的方式不再用于健康助手；现在通过网站保存个人配置。

官方资料：[兼容接口与模型参数](https://platform.minimax.cn/docs/api-reference/text-openai-api)、[获取 API Key](https://platform.minimax.cn/docs/guides/quickstart-preparation)。模型使用权限与费用由 MiniMax 账号决定。

## 数据范围和行为

- 只读本人近 7 天或 30 天的有效健康记录与饮食每日热量汇总，包含今天。记录更正与隐藏状态沿用现有规则。
- 发给模型的内容只有问题、日期、每日数值、记录覆盖情况及来源引用编号。不发送登录身份、邮箱、财务数据、健康记录 ID、原始健康样本、饮食名称、份量或备注。真实来源名称仅用于站内引用表。
- 缺失数据保留未知；饮食热量只代表已记录且填了热量的部分。活动能量不是全天总消耗，不能直接与摄入相减计算热量缺口。
- 回答与问题不写入数据库、浏览器持久存储或应用日志。MiniMax 对请求的处理适用其服务条款，本站不承诺第三方不保留请求。
- 页面只显示最终回答文本，不执行模型输出，不暴露推理内容，也不提供修改记录的工具。
- 每位用户每分钟最多 3 次、北京时间每天最多 20 次模型请求。额度按请求尝试计数，失败请求也计数；不自动重试可能产生费用的请求。额度计数存储在 D1 的 `ai_usage_limits`，不含问题或健康数据。

## 验证

配置完成后，先保存，再点击“测试连接”验证账号及模型访问。个人数据仅在健康助手页面明确勾选并发送后调用。未保存 Key 时，健康助手入口与摘要预览仍可用，分析按钮不可用，不会生成示例回答冒充真实模型结果。
