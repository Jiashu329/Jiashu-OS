# 多账户与使用名单

每个人使用自己的 ChatGPT 账号登录。所有业务记录继续以 Sites 提供的站点内稳定用户 ID 作为 owner；健康、饮食、财务、同步连接、周行动和月结互相隔离，创建者的现有记录不迁移给其他人。MiniMax 服务由创建者统一配置，成员直接使用；共享服务配置不共享个人业务记录。

创建者从“当前账户 → 管理使用名单”（`/settings/access`）配置允许登录的邮箱，可以添加、停用及恢复成员。网站不发送邮件，创建者自行将网站链接提供给成员。首次登录用平台验证的邮箱找到邀请并原子绑定用户 ID，之后按已绑定 ID 判断；邮箱变化不会重新分配记录，停用也不能通过换邮箱绕过。停用保留历史数据，后续请求会被拒绝。普通成员无法列出或修改名单，创建者也没有通过这套界面读取其他成员业务数据的入口。

## 首次部署

在 Sites 的服务端运行配置中设置 `APP_OWNER_EMAIL` 为已经核对的站点创建者邮箱。仅这个经过 Sites 登录验证的邮箱可首次绑定真实的站点内 ID 到 `app_owner_identity`；其他先到访的人不会成为创建者。此后该绑定不会因相同邮箱的其他用户 ID 而改变。已知真实站点内 ID 时，也可以显式设置 `APP_OWNER_USER_ID`；不要用 Sites 全局账户 UUID 代替站点内身份。

没有有效创建者配置时，业务页面和 API 拒绝访问。迁移 `0019_invited_accounts.sql` 只增加授权表，不修改既有业务数据。授权名单、管理操作回执和创建者绑定不属于业务备份，恢复业务备份不能扩大权限。

要让创建者在网站内自行配置新成员，托管层必须允许访客到达登录入口；业务访问仍由网站名单逐请求控制。切换既有 Sites 访问范围前，先由创建者明确确认。未获准的已登录访客显示拒绝页，匿名访客先登录，不提供业务记录。

## 换号与共享设备

每个经过认证的 HTML 页面绑定服务器渲染时的用户 ID。API 请求会重新核对当前登录身份，并携带页面 owner；服务器拒绝旧页面、无 owner 写入或账号不一致的请求。切号后旧内容被遮盖，原账号的草稿和待确认操作保留在原分区，不会提交给新账号。刷新后才进入新账号的空间。

本机草稿按用户分区，但同一浏览器配置的存储不是设备级保密边界。共用设备时应分别使用浏览器用户配置。未提交的草稿不上传、不会因为添加成员而共享。

## 家庭账本协作

每个人保留一本自己拥有的家庭账本，也可以加入多本他人拥有的家庭账本。“家庭账本”选择器在财务总览、余额核对、财务目标、应急储备和月度复盘中保持所选范围；个人账本继续独立。

账本拥有人在“家庭 → 我的家庭账本 → 管理协作者”填写对方登录网站使用的邮箱，创建30天有效的站内邀请。网站不发送邮件；受邀人登录后，在家庭账本的邀请区明确接受或婉拒。接受后才能选择并共同编辑该账本。家庭邀请不会授予网站登录资格；新用户仍需已有网站准入权限。账本拥有人与网站创建者是不同权限，普通网站成员也可以邀请他人协作自己的家庭账本，网站创建者不能因此管理别人的家庭账本。

只有账本拥有人能邀请、撤销待接受邀请、调整成员角色或移除协作者。可编辑成员可以维护所选家庭账本的账户、余额、财务目标、应急储备与月结；只读成员仅可查看这些资料及协作动态。成员不能查看拥有人的个人账本或管理成员。已有记录保留原始数据所有者及UUID，协作编辑另记实际操作者和操作标识。每位拥有人的自有家庭账本映射唯一，不能通过不同名称把同一拥有人的现有家庭记录伪装为多本。

每次读取、编辑及原请求重试均重新核对账本权限；业务写入与成员授权复核、操作者记录在同一事务中完成。成员被移除或授权版本变化后，旧页面会锁定并隐藏原账本内容，原草稿与待确认操作保留在原账本、原授权版本下，不会自动提交到自己的账本。重新邀请须再次明确接受，旧请求不能借用新的授权版本恢复写入。

完整备份和恢复始终限当前用户自己拥有的数据，不代理协作账本拥有人；协作关系及操作授权表不属于业务备份。家庭账本单独导出仅限该账本拥有人。首页财务提示仍统计本人拥有的账本，加入的协作账本从家庭选择器进入，不与本人财务或健康资料静默合并。

协作动态入口为 `/finance/activity`，展示当前家庭账本的实际操作者、动作和时间。站内消息入口为 `/notifications`，按当前权限显示邀请、协作变更及本人待处理提醒。详见[食物库维护、家庭协作与站内消息](catalog-collaboration-notifications.md)。
