# 数据与操作可靠性

## 读取失败

首页、健康与财务的页面请求覆盖连接与响应体读取，默认读取截止时间为 20 秒，写入为 30 秒。服务端主读取采用 8 秒截止时间；首页独立呈现健康、个人账本、家庭账本的状态。失败后可以主动重试，本页已经读取成功的数据会注明上次成功时间。

诊断日志仅包含固定事件、模块、原因和随机诊断编号，不记录健康、财务内容或凭据。读取截止不会撤销数据库中已经开始执行的写入；财务提交因此采用下面的待确认流程。

## 完整备份与恢复

从“数据连接 → 数据备份”进入 `/data`。完整备份 v2 覆盖全部日期的 22 类业务数据：健康原始记录、同步回执、导入与回退历史、逐指标同步诊断、健康目标及生效历史、体重计划、健康更正及修改历史、饮食记录（含营养素、删除状态与食物来源快照）、逐项营养来源与修改历史、每日营养目标、历史恢复回执、常用食物、饮食记录完整度、餐次复制与批量提交回执、两个账本的账户和余额、余额更正历史、财务目标与应急储备设置。

备份不包含 AI 凭据、AI 调用计数、同步设备及连接密钥；浏览器内的未提交草稿和待确认请求不属于业务备份。批量提交、餐次复制和历史恢复回执与其饮食记录一起恢复，用于拒绝重复写入。换环境后需要重新配置相应连接。下载的 JSON 包含个人业务数据，应由用户自行妥善保存。

恢复分两步：先预览覆盖数量和冲突，再勾选确认执行。恢复只补入缺少的记录，相同记录跳过；有差异或关联不完整时整包停止。预览后数据发生变化，需要重新预览。财务金额使用最小货币单位字符串，余额的原先相对顺序会保留。

仍接受此前下载的完整备份 v1，缺少的新数据表按空表处理。旧设置恢复时会更新保存版本，防止恢复前打开的空设置页面覆盖新恢复数据；旧健康目标会生成历史／恢复基线，保留旧版按当前目标评价历史的结果。基线日期 `1970-01-01` 表示兼容旧版的评价口径，不代表用户实际在该日设置目标。预览和结果会说明自动生成的基线条数。已有健康目标的历史需要增补时停止整包恢复，避免改写历史评价而保留旧保存版本。

同时支持早期 13 表 v1、包含营养扩展的 v1 及此前 19 表 v2 文件，备份格式仍为 v2。缺少每日营养目标、饮食历史和历史恢复回执时按空表处理；旧营养素和来源字段保持未知，不伪造历史。账户元数据版本与财务目标版本缺失时按兼容初值 1 读取；相同业务记录跳过时保留数据库现有版本，不降低编辑保护。

缺少食物来源列时按空来源兼容；缺少常用食物、完整度或批量回执时按空表兼容。食物来源快照须能与当前可信食物库的版本、份量和热量数学核对；不支持的历史来源版本会明确拒绝，避免用新版数值悄悄改写旧记录。恢复时，来源完整度只补入原先不存在的日期；目标已有标记不被来源覆盖，新增食物仍按正常触发器规则使相关日期重新进入记录中。容量检查会计入触发器生成的日期状态与版本变化。

当前版本限制单包 8 MiB、20,000 行，并在执行前检查 48 条查询预算；超过容量时明确拒绝，不截断导出或部分恢复。22 类数据由一条白名单联合查询读取为一致快照，不把整表聚合成单个大 JSON 单元。恢复结果不确定时重新预览，相同记录仍会跳过。已有数据与备份合并后仍须满足常用食物最多 100 项和同步诊断最多 100 次的规则。

## 财务更正与待确认提交

在账户详情的余额历史选择“更正”或“作废”，填写原因，查看对当前余额的影响后提交。原始余额与每次修改都保留。预览后账户余额发生变化，必须重新读取与预览。账户最后一条有效余额不能直接作废，可以更正金额／日期，或将不再使用的账户归档。

创建账户、追加余额和余额更正会在发送前固定原内容及操作标识。网络中断、超时或服务端暂时不可用时，当前设备保留待确认原操作；关闭弹窗、刷新或重开浏览器后可以主动继续确认。确认使用同一标识，不自动重试或改成新建。恢复信息按登录用户隔离，服务端确认成功后清理；明确拒绝后可以修改再提交。设备存储不可用时显示提示，无法保留提交标识则不发送新请求。

## 编辑版本与本机草稿

账户名称、类型、备注及归档／恢复使用独立的元数据版本，财务目标编辑、归档／恢复也检查读取时的版本。过期写入返回冲突，旧客户端缺少版本时明确拒绝；它们不会覆盖新内容。账户元数据版本与余额版本独立，原创建与余额待确认请求的标识、内容摘要保持不变。API 分别返回账户的 `metadataRevision` 和目标的 `revision`，修改必须提交 `expectedRevision`；过期返回 `409 FINANCE_METADATA_CONFLICT`。

冲突后保留表单输入并暂停保存。本人点击“读取最新内容”查看新值，核对后再次提交；读取本身不会发送草稿，也不会由后台刷新悄悄提高草稿版本。

首页“未完成的记录”汇总本机普通草稿和待确认操作，后者优先显示。普通草稿可预览、主动恢复或删除；恢复检查表单原值和记录上下文，遇到变化只展示原草稿，不覆盖新输入。普通草稿保留最多 30 天；待确认操作不因普通草稿到期而清理，不能作为普通草稿直接删除。

恢复内容保存在当前浏览器的 localStorage，按登录用户隔离，不上传服务器、不跨设备同步，也不包含在完整业务备份内；清除浏览器数据会移除它们。密码、API 密钥等凭据字段和健康助手对话不纳入草稿。恢复入口不会自动保存或调用 AI，用户仍需核对后提交。

## 健康导入预览与回退

手动选择文件或粘贴 JSON 后先查看预览，核对指标、日期、增改数量和来源。同源设备同步可继续自动完成，跨来源覆盖必须经过明确确认；已有手工更正或屏蔽状态会在预览中说明。

同步页面可以查看最近 20 次导入并填写原因回退整批。回退仅恢复原始同步数据，保留审计；若已有后续同步，或删除新导入原值会破坏后续手工修改，则整批拒绝回退，并指向记录管理逐条核对。已经回退的同一批次再次提交不会重新生效，需要重新导出新的批次。
