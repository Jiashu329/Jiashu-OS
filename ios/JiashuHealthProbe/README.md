# Jiashu OS · iPhone 原生客户端

使用 SwiftUI，连接现有阿里云服务 **https://www.treefund.asia**。工程名和 Bundle Identifier 沿用 JiashuHealthProbe，便于升级此前安装的测试 App；显示名为 Jiashu OS。

## 当前功能

- App 内邮箱密码登录、设备会话续期与退出，不再依赖 Safari 交接健康数据。
- 原生首页展示活动与睡眠、营养已知小计、分币种财务概况和最近书影音记录，并提供记一餐、待确认记录和本周行动入口。自动同步的体重与体成分在健康页查看。
- Apple Health 只读授权：步数、活动能量、睡眠、体重、去脂体重。
- 一次确认这台 iPhone 为本人日常同步来源，之后自动处理该通道内的手机／手表来源变化，不再逐批确认。
- 开启自动同步后，回到前台时检查是否需要刷新最近30天，HealthKit变化通知触发时刷新最近7天；也可在“我的”补同步7／30／90天。
- 7／30／90／180／360天健康趋势、睡眠分期明细、健康目标及同步历史。
- 五项健康指标的人工补录、基础饮食记录、当前／上周回顾、本周行动及反馈。

- 原生财务：个人／家庭账本、成员邀请与权限、账户分类与流动性、余额核对及修正预览、目标、应急储备、月结与历史、活动记录和导出。
- 完整饮食：记录编辑／删除／历史恢复、营养来源与未知值、食物库与饮品配置、收藏及餐次复制、自建食物／食谱／整餐模板、文字／照片识别后逐条核对、目标测算和回顾。
- 从饮食进入「我的菜谱」，粘贴小红书或下厨房链接收藏。成品照可以保存到自建菜谱或已收藏菜谱的制作记录。
- 健康工作区：自选日期和同范围导出、来源与睡眠作息分析、记录更正及屏蔽、目标生效历史、体重周期、健康助手、逐指标同步诊断与导入回退。
- 书影音：筛选与详情、本人备注标签和隐藏恢复、分类与封面、资料补全及评分、公开同步进度、文件／剪贴板导入预览确认和清空核对。
- 设置与数据：消息分类和未读管理、服务配置与明确测试、管理员用户及访问名单、同步连接、单文件及完整分卷备份和原子恢复。

主导航为“今天／健康／财务／书影音／我的”。每周复盘保留在首页与健康中，完整饮食从健康进入；新增功能均由原生 SwiftUI 页面操作。功能对应和真实外部限制见 [完整迁移核对表](../../docs/ios-feature-parity.md)。豆瓣私密资料仍需由本人登录的来源工具导出，iOS 不运行桌面浏览器扩展；App 提供原生文件与剪贴板解析、预览和确认。

## 安装与服务版本

**先部署包含新原生接口和 `0037_nutrition_recipes` 迁移的后端，再安装此客户端。** 菜谱、制作记录和操作回执使用新增数据表，既有健康同步通道沿用 `0036_native_health_channels`。

1. Mac 安装支持手机系统版本的 Xcode，下载当前分支完整工程。
2. 打开 `JiashuHealthProbe.xcodeproj`。
3. Xcode → Settings → Apple Accounts，登录自己的 Apple 账号。
4. TARGETS → JiashuHealthProbe → Signing & Capabilities，选择自己的 Team，保留自动签名。若要覆盖旧测试App，保持原来使用的Bundle Identifier；新安装可使用自己的唯一标识。
5. 连接并信任iPhone，在手机开启开发者模式，选择真实iPhone，点击Run。
6. 在App使用网站现有账号登录，进入“我的 → 同步中心”，连接这台iPhone并选择健康读取权限。
7. 在日常设备确认页填写名称，核对将替换的设备并点击“确认”。取消不会选择设备。
8. 对比苹果健康与App的同一北京时间日期，特别核对昨天的步数、能量、睡眠及一次体重，再检查服务器同步回执。

工程目标为 iOS17及以上。免费开发签名通常7天到期，届时需用Xcode重新签名；长期家庭分发可使用付费开发者账号和TestFlight。HealthKit后台通知需要相应签名能力，实际支持以Xcode生成的profile和真机为准。

## 日常使用与界面

「今天」的「记一餐」直接打开记录表单，其中的常吃和前一天同餐可带入可编辑草稿。保存结果待确认时从首页回到原记录核对。已选周行动可以从首页打开并填写反馈，尚未选行动时可根据上一周的记录进入复盘。消息集中在顶部铃铛。同步授权、日常设备、同步状态和历史诊断在「我的 → 同步中心」查看。

首页营养展示已知小计与未知项目。财务金额按账本和币种分别读取，日期采用实际余额日期。书影音展示最近记录。缺失值、读取失败和真实零值分别显示。估算体脂在健康页查看，使用同源同次测量配对。

健康使用同一个趋势范围页，选中指标和已加载日期继续传递到记录与助手。饮食的常吃、拍照、文字、食品库与模板共享日期和餐次；保存时就地核对。财务保持明确的账本、成员权限和币种，支持原生日期输入及月度逐账户核对。书影音支持封面网格、列表和独立整理模式。

「我的菜谱」接受小红书与下厨房分享链接或完整分享文案。可读取的公开资料可带入菜谱，遇到访问限制时可保留原文链接并手动填入菜名、食材和做法。菜谱及成品照保存在本人账号下，可随完整业务备份迁移。要记录一餐，需在饮食表单中确认实际吃的份量和餐次。

同账户会话续期不重建导航，切换账户才重置可见内容。首次打开不等待完整健康同步；暂时读取失败保留已取得数据，并明确显示读取失败。保存结果不明仍保留原请求，不把待确认显示为已保存。

## 日常同步来源：每台设备确认一次

系统健康读取授权与网站的日常同步设备选择是两件事。首次接入时，App先请求系统读取权限，再由本人明确选择这台iPhone作为当前网站账号的日常来源。此后，同一通道内步数、活动能量、睡眠、体重及去脂体重的可读记录变化自动参与同步；手机与手表的记录来源变化不再要求逐批勾选确认。原有人工更正及屏蔽继续生效。

每个网站账号同时选择一个日常设备。App在本机生成随机设备凭据，按网站地址和用户ID隔离保存在Keychain，使用 `AfterFirstUnlockThisDeviceOnly`，不迁移到其他设备。服务器仅保存凭据摘要；凭据不进入UserDefaults、URL、日志或业务备份。设备凭据与登录会话独立：退出登录会暂停此账户的App同步，但保留设备选择及本机凭据；同一用户重新登录可恢复原选择，切换用户不共用设备凭据或来源选择。

选定日常设备后，服务器拒绝旧快捷指令或其他设备向该日常通道导入记录，避免旧来源覆盖原生App的数据。在另一台iPhone明确确认替换时，旧设备的日常同步凭据会被撤销，旧请求不会自动重新选回旧设备。设置页读取状态只显示当前选择，不替用户做选择。

“自动同步”开关关闭时只暂停这台App的上传，仍保留日常设备选择，旧快捷指令也不会因此恢复写入。只有当前选定设备可在“我的”点击“解除日常同步来源”并明确确认；解除会撤销当前设备凭据，既有服务器记录与人工更正保留。解除后如需再次接入，需重新确认新的设备连接。

## 自动同步与授权

苹果健康权限面板必须由本人操作，App不代替用户批准。权限请求结束也不表示所有类型均被授权；HealthKit不会可靠区分“没有记录”和“未允许读取”，这些情况均不补成零。

自动同步开关按网站用户分别保存。健康内容和密码不写入UserDefaults；可撤销会话、独立的日常设备凭据及已提交待确认的人工操作保存在本机Keychain，使用AfterFirstUnlockThisDeviceOnly。

回到前台时，App检查距离最近一次自动同步尝试是否已超过60秒，满足条件才补查最近30天；这不是每60秒运行的定时任务。HealthKit Observer变化通知触发最近7天的核对，通知完成回调等待有上限的同步结束，并发通知合并后补跑。后台同步预算25秒（包括等待已有同步），前台120秒，并响应系统后台执行到期取消。后台通知若在等待时耗尽预算，结束回调，不再为这次通知启动上传。iOS决定实际唤醒时机，App被强制结束、权限撤销或设备锁定时无法承诺后台上传。页面显示实际服务器确认结果，可按需手动重试。

自动同步失败在同步状态中显示原因，避免前台激活或后台通知反复弹窗；本人点击的手动重试仍会明确显示错误。失败批次不会上传部分记录，认证失效及日常设备被替换时仍停止同步。

读取、睡眠窗口与导出校验统一使用不晚于实际读取时刻的毫秒截止时间，避免亚毫秒时间在序列化后误报为未来记录，或令睡眠分期超过导出窗口。真正无效的数值、未来记录及超量批次仍会被拒绝。

步数和活动能量由HealthKit系统统计合并，不相加手机与手表的原始样本。日期沿用网站Asia/Shanghai口径。睡眠按前一天中午至所选日中午的窗口，选择一个稳定来源并对区间去重；清醒和卧床不计入睡眠。体重类保留单次测量与稳定UUID。同步仍核对服务器最新数据和通道权限，首次日常设备确认之后无需逐批确认记录来源；通道被替换、撤销或状态无法核实时停止上传，不退回旧来源继续写入。

现有导入为upsert，苹果健康删除的历史样本不会自动删除服务端记录。一次最多1000条／512KB，超限会明确失败，应缩小补同步范围，不会截断后显示成功。更多历史可分段迁入，当前自动同步不声称镜像用户终身完整健康库。

## 原生接口与数据归属

- `POST /api/native/auth/login`：`{email,password}`。
- `POST /api/native/auth/refresh`、`POST /api/native/auth/logout`：Bearer会话。
- `GET /api/native/sync/channel`：读取当前日常通道；附带本机 `X-Sync-Device` 时确认是否为当前设备，不修改选择。
- `PUT /api/native/sync/channel`：本人明确确认后提交设备凭据、名称及 `expectedRevision`；同一凭据重试核对原选择，不重复创建连接。
- `DELETE /api/native/sync/channel`：当前设备携带自己的凭据和版本，明确解除通道。
- 健康、饮食、财务、书影音、消息、设置与备份API从`/api/native/`进入服务端逐路由和方法的精确白名单；动态标识仅在既定路径中解析，复用已有业务规则、用户隔离、角色和账本成员授权、目标历史、导入预览和操作回执。
- 会话使用独立签名域，每次检查账户启用状态、凭据版本和撤销状态。退出不影响同账号其他浏览器的独立会话。
- 原生请求不接受浏览器Origin或Cookie；客户端禁用Cookie、缓存及重定向。供应商AI密钥继续留在服务器。

## 验证

GitHub的iOS HealthKit checks在macOS执行工程结构检查、模拟器编译和XCTest，包括日期／睡眠区间、五指标导出、API交互、真实Keychain与账号切换竞态。模拟器CI使用独立的临时ad-hoc身份启用Keychain，既不使用个人Apple账号，也不改变真机签名配置。测试后保留匿名登录截图。

Self-hosted checks启动实际构建的服务器，覆盖原生登录→middleware→首页→五指标预览／导入／查询→人工补录与饮食→退出及重启后撤销。普通单测、生产构建及原网页浏览器验收继续执行。

日常通道还需核对：第一次明确选择、同一凭据重试、旧快捷指令拒绝写入、手机／手表来源变化无需再次确认、暂停后保留选择、另一设备替换后旧设备停止上传、明确解除后凭据失效，以及切换账号时的凭据隔离。

模拟器不会包含你的真实健康数据。授权弹窗、数据一致性、个人签名和iPhone后台唤醒仍需真机核对；CI通过不等同于这些项目通过。

本地结构检查：`python3 scripts/verify-project.py`。完整模拟器验证以仓库`.github/workflows/ios-healthkit.yml`为准。

## 草稿、导出和完整备份

各功能的未提交填写和已发送待确认操作分别保存。敏感内容使用当前用户、服务端及功能范围隔离的 Keychain 或 AES-GCM 加密文件；文件密钥仅留在设备 Keychain，不进入业务备份。重新进入后由本人选择恢复，不自动提交。版本变化会保留填写并要求重新核对，网络结果不明时继续使用原请求标识与原始内容。

财务金额按十进制字符串与最小货币单位整数保持精度，不转换成浮点汇率或重算服务器汇总。未知营养素和缺失健康值保持未知。

完整分卷保存清单和全部卷，恢复时原样保留有摘要的 JSON 值字节及属性顺序。App 先读取服务器预览，展示新增、跳过、冲突及字段差异；冲突不会自动覆盖。确认后再由服务器核对摘要并事务恢复。导出通过系统分享保存到“文件”，生成与本人确认妥善保存分别显示；App 不把生成文件解释为已经完成外部保存。
